---
title: "Vehicles"
description: "Configure EVs in evcc to enable SoC reading, target charging, and automatic mode switching."
---

Configuring your vehicle allows evcc to read its battery state of charge (SoC) from the manufacturer's cloud API. With SoC data, evcc can stop charging at a target level, display remaining range in the UI, and run charge planning with a departure time.

## Defining a vehicle

Add each vehicle under the `vehicles:` key and give it a unique name:

```yaml
vehicles:
  - name: car1
    type: renault
    title: Zoe          # display name in the UI
    capacity: 60        # battery capacity in kWh
    user: myuser
    password: mypassword
    vin: WREN...
    onIdentify:
      mode: pv          # switch to PV mode when this vehicle is identified
```

## Vehicle configuration parameters

<ParamField path="name" type="string" required>
  A unique identifier for this vehicle. Used when pre-assigning a vehicle to a loadpoint.
</ParamField>

<ParamField path="type" type="string" required>
  The vehicle integration type (e.g. `tesla`, `vw`, `renault`, `hyundai`, `bmw`).
</ParamField>

<ParamField path="title" type="string">
  Human-readable name shown in the UI. Defaults to the `name` value.
</ParamField>

<ParamField path="capacity" type="number">
  Usable battery capacity in kWh. Enables SoC estimation when the API is unavailable and improves accuracy of charge planning.
</ParamField>

<ParamField path="vin" type="string">
  Vehicle identification number. Required when you have multiple vehicles of the same brand in the same account.
</ParamField>

<ParamField path="onIdentify" type="object">
  Settings to apply automatically when evcc identifies this vehicle at a loadpoint (via RFID or vehicle API match). Supports `mode`, `minSoc`, `targetSoc`, and `planSoc`.
</ParamField>

  <Tab title="Hyundai / Kia">
    Hyundai (Bluelink) and Kia (Connect) share the same backend. They require a `refresh_token` rather than the account password.

    ```yaml

        type: hyundai
        title: IONIQ 5
        capacity: 72
        user: myuser@example.com
        password: <refresh_token>   # NOT your account password
    ```

    See the [evcc wiki](https://github.com/evcc-io/evcc/wiki/Hyundai-Kia:-Refresh-Token) for instructions on obtaining the refresh token.
  </Tab>
  <Tab title="Offline / generic">
    For vehicles without a cloud API (or when you want to avoid API polling entirely), use the offline type. SoC must be entered manually in the UI.

    ```yaml
    vehicles:
      - name: leaf
        type: custom
        title: Leaf
        capacity: 40
        features:
          - offline   # marks vehicle as not having an API
        soc:
          source: const
          value: 0
    ```

    This is also the right choice for vehicles that are supported by another integration (e.g. OVMS, TeslaFi, TeslaLogger, Teslamate) that exports SoC via MQTT or HTTP.
  </Tab>
</Tabs>

## SoC polling settings

evcc queries the vehicle API to update the state of charge. By default it only polls while charging to avoid draining the 12 V battery and to respect manufacturer API rate limits.

```yaml
loadpoints:
  - title: Garage
    charger: wallbe
    soc:
      poll:
        # charging — update SoC only while charging (recommended default)
        # connected — update while connected (charging or not), on the interval below
        # always    — always update regardless of connection (single vehicle only)
        mode: charging
        interval: 60m     # how often to poll when NOT charging (connected/always modes)
      estimate: true      # interpolate SoC between API updates (recommended)
```

<Warning>
  Changing `poll.mode` to `connected` or `always` may drain your vehicle's 12 V battery or cause the manufacturer to rate-limit or ban your API access. Use at your own risk.
</Warning>

## `onIdentify` — automatic mode switching

When evcc identifies a vehicle at a loadpoint (via RFID tag read or API match), it can automatically apply preferred settings for that vehicle:

```yaml
vehicles:
  - name: car1
    type: vw
    title: ID.3
    capacity: 58
    user: myuser@example.com
    password: mypassword
    onIdentify:
      mode: pv          # switch to PV-only mode when this car plugs in
      minSoc: 20        # always charge to at least 20% (e.g. for departure readiness)
      targetSoc: 80     # stop at 80% by default
```

Supported `onIdentify` fields:

| Field       | Description                                                        |
| ----------- | ------------------------------------------------------------------ |
| `mode`      | Default charging mode: `off`, `now`, `minpv`, or `pv`             |
| `minSoc`    | Minimum SoC % to reach before switching to PV-only charging        |
| `targetSoc` | SoC % at which charging stops                                      |
| `planSoc`   | Target SoC for scheduled (plan) charging                           |

## Guest vehicles

When an unknown vehicle connects (no RFID match, no API identification), evcc treats it as a **guest**. You can configure push notifications for guest connections:

```yaml
messaging:
  events:
    guest:
      title: Unknown vehicle
      msg: Unknown vehicle, guest connected?
```

Guest vehicles charge in the loadpoint's default mode (`mode:` in `loadpoints:`). Set `mode: "off"` if the charger is publicly accessible and you want to prevent unintended charging by unknown vehicles.
