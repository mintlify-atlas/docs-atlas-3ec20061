title: "Loadpoints"
description: "Control each EV charge point — charging mode, SoC and energy limits, charging plans, phase selection, thresholds, and vehicle assignment."
---

A loadpoint represents a single EV charge point (wallbox). evcc numbers loadpoints starting at `1`. You can find the ID from the `GET /api/state` response where `loadpoints` is a zero-indexed array — loadpoint at index `0` has API ID `1`.

All write endpoints on this page require an authenticated session. See [Authentication](/api/auth).

---

## Mode control

### POST /api/loadpoints/\{id\}/mode/\{mode\}

Set the charging mode for a loadpoint.

<ParamField path="id" type="integer" required>
  Loadpoint index, starting at `1`.
</ParamField>

<ParamField path="mode" type="string" required>
  One of:
  - `off` — charging disabled
  - `now` — charge at maximum power immediately
  - `minpv` — charge at minimum current, boost with solar surplus
  - `pv` — charge only when solar surplus is available
</ParamField>

**Response:**

<ResponseField name="result" type="string">
  The active mode after the update (`off`, `now`, `minpv`, or `pv`).
</ResponseField>

```bash
# Switch to solar-only mode
curl -b cookies.txt -X POST \
  http://evcc.local:7070/api/loadpoints/1/mode/pv
```

```json
{ "result": "pv" }
```

## Phase control

### POST /api/loadpoints/\{id\}/phases/\{phases\}

Set the allowed number of charging phases. For chargers that support automatic phase switching, this selects the desired mode. For manually switched chargers, it tells evcc how many phases are physically connected.

<ParamField path="id" type="integer" required>
  Loadpoint index, starting at `1`.
</ParamField>

<ParamField path="phases" type="string" required>
  One of:
  - `0` — automatic (charger decides)
  - `1` — force single-phase charging
  - `3` — force three-phase charging
</ParamField>

**Response:**

<ResponseField name="result" type="number">
  The active phase setting.
</ResponseField>

| Status | Meaning |
|---|---|
| `200` | Phase setting updated. |
| `400` | Invalid value (e.g. `0` on a charger that cannot auto-switch). |

```bash
curl -b cookies.txt -X POST \
  http://evcc.local:7070/api/loadpoints/1/phases/1
```

```json
{ "result": 1 }
```

## Solar thresholds

These settings control when evcc starts and stops charging in `pv` and `minpv` modes.

### POST /api/loadpoints/\{id\}/enable/threshold/\{threshold\}

Set the surplus power threshold to start charging. Charging begins when available solar surplus exceeds this value.

<ParamField path="id" type="integer" required>
  Loadpoint index, starting at `1`.
</ParamField>

<ParamField path="threshold" type="number" required>
  Power threshold in watts. Minimum `0`.
</ParamField>

**Response:**

<ResponseField name="result" type="number">
  The updated enable threshold in W.
</ResponseField>

```bash
curl -b cookies.txt -X POST \
  http://evcc.local:7070/api/loadpoints/1/enable/threshold/1400
```

```json
{ "result": 1400 }
```

---

### POST /api/loadpoints/\{id\}/enable/delay/\{delay\}

Set the delay before charging starts once the enable threshold is exceeded. Prevents brief surplus spikes from triggering a charging session.

<ParamField path="id" type="integer" required>
  Loadpoint index, starting at `1`.
</ParamField>

<ParamField path="delay" type="integer" required>
  Delay in seconds.
</ParamField>

**Response:**

<ResponseField name="result" type="integer">
  The stored delay in **nanoseconds** (multiply your input seconds by 1,000,000,000).
</ResponseField>

```bash
curl -b cookies.txt -X POST \
  http://evcc.local:7070/api/loadpoints/1/enable/delay/60
```

```json
{ "result": 60000000000 }
```

<Note>
  The response value is in nanoseconds (Go's native duration format), so a 60-second delay returns `60000000000`.
</Note>

---

## Smart cost limits

### POST /api/loadpoints/\{id\}/smartcostlimit/\{cost\}

Set a cost or emission limit for fast-charging using grid energy. When a dynamic tariff is configured, charging is allowed at full power when the price is below this limit. When a CO₂ tariff is configured, the value is treated as a g/kWh threshold.

<ParamField path="id" type="integer" required>
  Loadpoint index, starting at `1`.
</ParamField>

<ParamField path="cost" type="number" required>
  Cost limit in your configured currency (default EUR/kWh) or CO₂ in g/kWh.
</ParamField>

**Response:**

<ResponseField name="result" type="number">
  The updated smart cost limit.
</ResponseField>

```bash

  http://evcc.local:7070/api/loadpoints/1/smartcostlimit/0.20
```

```json
{ "result": 0.20 }
```

## Charging plans

Charging plans let you schedule a charging session to reach a target SoC or energy amount by a specific time. evcc uses tariff data to fill the cheapest hours.

### GET /api/loadpoints/\{id\}/plan

Get the current active charging plan for a loadpoint.

<ParamField path="id" type="integer" required>
  Loadpoint index, starting at `1`.
</ParamField>

**Response:**

<ResponseField name="result" type="object">
  <Expandable title="result fields">
    <ResponseField name="planId" type="integer">
      Internal plan identifier.
    </ResponseField>
    <ResponseField name="planTime" type="string">
      Target completion time in RFC 3339 format.
    </ResponseField>
    <ResponseField name="duration" type="integer">
      Required charging duration in seconds.
    </ResponseField>
    <ResponseField name="power" type="number">
      Charging power used for plan calculation in W.
    </ResponseField>
    <ResponseField name="plan" type="array">
      Array of rate slots, each with `start`, `end`, and `value` fields.
    </ResponseField>
  </Expandable>
</ResponseField>

```bash
curl http://evcc.local:7070/api/loadpoints/1/plan
```

```json
{
  "result": {
    "planId": 1,
    "planTime": "2025-07-20T07:00:00Z",
    "duration": 7200,
    "power": 7400,
    "plan": [
      { "start": "2025-07-19T23:00:00Z", "end": "2025-07-20T01:00:00Z", "value": 0.12 },
      { "start": "2025-07-20T05:00:00Z", "end": "2025-07-20T07:00:00Z", "value": 0.15 }
    ]
  }
}
```

## Battery boost

### POST /api/loadpoints/\{id\}/batteryboost/\{enable\}

Enable or disable battery boost for a loadpoint. When active, home battery power supplements solar power to charge the vehicle faster, until the home battery drops to the configured SoC limit.

<ParamField path="id" type="integer" required>
  Loadpoint index, starting at `1`.
</ParamField>

<ParamField path="enable" type="string" required>
  `true` or `1` to enable, `false` or `0` to disable.
</ParamField>

**Response:**

<ResponseField name="result" type="boolean">
  Whether battery boost is now active.
</ResponseField>

```bash
curl -b cookies.txt -X POST \
  http://evcc.local:7070/api/loadpoints/1/batteryboost/true
```

```json
{ "result": true }
```

<Note>
  Battery boost does not work while the home battery is on hold (e.g. during fast charging with discharge prevention enabled).
</Note>

---

### POST /api/loadpoints/\{id\}/batteryboostlimit/\{soc\}

Set the home battery SoC limit for battery boost. Boost stops when the home battery reaches this level. Default is `100`, which effectively disables the feature in the UI.

<ParamField path="id" type="integer" required>
  Loadpoint index, starting at `1`.
</ParamField>

<ParamField path="soc" type="number" required>
  SoC limit in percent (0–100). Setting to `100` disables boost in the UI.
</ParamField>

**Response:**

<ResponseField name="result" type="integer">
  The updated battery boost SoC limit.
</ResponseField>

```bash
curl -b cookies.txt -X POST \
  http://evcc.local:7070/api/loadpoints/1/batteryboostlimit/20
```

```json
{ "result": 20 }
```
